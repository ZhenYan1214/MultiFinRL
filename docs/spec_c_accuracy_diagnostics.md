# Spec：分類準確率診斷（新聞訊號 vs. 類別不平衡）

狀態：已完成診斷，結論見下方「驗證結果」（來源：2026-08 grill-me 討論）

## Problem Statement

分類驗證（BULLISH/BEARISH/NEUTRAL 市場情緒預測）長期卡在偏低的準確率，而且每個類別的表現並不平均：模型幾乎永遠預測 NEUTRAL，從未正確辨識出任何一個 BEARISH 的日子。即使把歷史新聞資料從近乎全空補齊成完整五年的內容，準確率的變化也只有不到一個百分點，落在測試集只有 185 筆時的雜訊範圍內，而且各類別的表現模式（幾乎只猜 NEUTRAL）在補新聞前後完全一樣。這讓「資料完整度是提升準確率的主要槓桿」這個原本的假設變得可疑，需要先確認問題到底是出在資料，還是出在訓練方式、類別不平衡、標籤定義，或是還沒補齊的其他模態。

## Solution

在繼續投入更多資料（延伸時間範圍、擴充股票、補齊法說會逐字稿）之前，先做一組小規模的控制對照實驗，把兩個候選解釋分開驗證：（1）融合模型的最終準確率，是不是真的對「當天有沒有真實新聞內容」敏感；（2）目前訓練流程完全沒處理類別不平衡，是不是導致模型不管輸入是什麼都傾向直接猜多數類別。這兩個因素的所有有意義組合會一次跑完，而不是一個一個依序測，因為重跑分類驗證階段的成本很低（不需要重跑最花時間的多模態編碼步驟）。用實測結果來決定下一步要投資在哪裡——繼續擴充資料、修正訓練方式，還是重新檢討標籤定義本身——而不是繼續憑假設行動。

## User Stories / Scenarios

1. 作為團隊成員，我想知道融合模型是不是真的有在使用新補齊的歷史新聞內容，這樣才不會在不確定有沒有用的情況下持續擴充新聞資料。

2. 作為團隊成員，我想知道目前三分類標籤的類別不平衡，是不是導致模型塌縮成只猜多數類別的原因，這樣才能區分「這是資料問題」還是「這是訓練方式問題」。

3. 作為團隊成員，我希望新聞有無、類別加權這兩個診斷因素能被乾淨地分開測試，這樣任何準確率的變化才能歸因到正確的原因，而不是兩個因素混在一起分不清楚。

4. 作為團隊成員，我希望這些診斷實驗成本要低、不需要重新抓取任何資料，也不需要重跑最花時間的多模態向量編碼步驟，這樣才能快速拿到答案，不用再等一次長時間的處理。

5. 作為團隊成員，我希望實驗結束後，原本已經產出的、基於真實新聞的向量能被還原回來，這樣專案不會停留在一個殘缺或曖昧不明的狀態。

6. 作為團隊成員，我想要一個不只看整體準確率的判讀標準，這樣測試集只有 185 筆時的些微準確率變化，才不會被誤判成有意義的發現。

7. 作為團隊成員，我希望這一輪先不去動現有的標籤定義，除非有很強的理由，這樣診斷實驗才不會因為同時改變了判斷依據（ground truth）而變得難以解讀。

8. 作為團隊成員，我希望有一份清楚排序過的資料擴充選項清單（延伸時間範圍、擴充股票、補齊法說會逐字稿），這樣一旦診斷結果指向「資料真的有幫助」，就知道接下來該做什麼、先做哪一個。

9. 作為團隊成員，我想知道延伸時間範圍比擴充股票便宜，這樣如果資料擴充真的是對的方向，可以先做便宜的那一個。

10. 作為團隊成員，我想知道法說會逐字稿的抓取工具從來沒有真正成功執行過，這樣診斷結果指向「該補文字資料」的當下，不會誤以為這條路已經準備好可以直接用。

11. 作為團隊成員，我希望模型架構層級的改動（例如微調視覺編碼器）這一輪明確排除在外，這樣心力才能先集中在成本低的診斷實驗上。

12. 作為團隊成員，我希望理解「沒有新聞」這個對照組其實仍然保留了透過檢索機制帶入的財報內容，這樣才不會誤解成這個實驗是在測試「完全沒有任何文字輸入」。

13. 作為團隊成員，我希望財報輸入天生的低日對日變化（同一份財報會被沿用將近一季，直到下一份發布為止）被記錄下來，即使這一輪的實驗不處理它，之後也不會被遺忘。

## Decisions

- 在繼續擴充訓練資料（延伸時間範圍、增加股票、補齊更多模態）之前，先跑控制對照實驗，確認模型是不是真的能從更完整的文字輸入中受益，以及類別不平衡有沒有掩蓋了這個效果。

- 診斷實驗測試兩個因素：每日文字編碼裡新聞內容的有無，以及分類訓練流程（包含融合層的表徵學習訓練步驟與最終的分類驗證步驟）裡有沒有加入類別權重。

- 兩個因素的所有有意義組合會一次跑完，不會一個一個依序測，因為重跑融合訓練與分類驗證的成本很低（真正昂貴的多模態編碼步驟不需要重跑）。

- 「沒有新聞」這個對照組的做法，是把已經算好的每日新聞表徵直接歸零，不重新抓取或重新編碼任何東西；視覺表徵與檢索機制帶入的表徵維持不動。

- 動手跑任何對照組之前，先備份目前已經算好的真實新聞表徵；診斷結論確定之後，把真實表徵還原回去，確保專案事後回到正常可用的狀態。

- 判斷每個對照組成功與否，主要看兩個少數類別的表現有沒有從目前貼著零的塌縮狀態真正動起來，不能只看整體準確率這一個數字，因為目前測試集規模小，一到兩個百分點的準確率變化跟雜訊無法區分。

- 這一輪不改動現有的標籤定義（固定天數的報酬區間、固定百分比門檻的三分類）。這件事先前就已經明確留待未來做對照實驗，此刻若跟診斷實驗同時改動，會讓結果無法乾淨解讀。如果診斷結果顯示：就算訓練方式正確、類別有加權、新聞資料也是真的，準確率依然沒有起色，那麼重新檢討標籤定義就會是下一個候選實驗。

- 如果診斷結果顯示模型確實能從真實新聞內容中受益，資料擴充的優先順序依序是：先延伸單一股票的時間範圍，讓其涵蓋範圍追上新聞歷史目前已達到的範圍（只需要重抓股價與圖表，不需要新的文字資料）；再考慮擴充到更多股票（需要重跑整條單一股票的資料流程，視為規模更大、更後面才做的投資）。

- 補齊法說會逐字稿的優先順序跟其他資料擴充一樣，排在診斷實驗之後；另外特別註記這條路目前未經驗證——抓取工具的程式碼雖然已經寫好，但從未成功端到端執行過，跟已經用真實輸出驗證過的新聞流程狀態不同。

- 財報內容日對日變化偏低（同一份財報會被沿用將近一季，直到下一份發布為止）被記錄為目前流程已知的特性，不當作缺陷處理，這一輪的實驗也不處理它。

- 模型架構層級的改動（例如微調目前凍結不動的視覺編碼器）這一輪明確排除在討論範圍之外，不受這裡任何決議影響。

## Open Questions / Out of Scope

- 標籤定義（報酬區間天數、百分比門檻）最終要不要改，這裡不做決定；留待這一輪診斷結束之後，當作獨立的未來對照實驗處理，不是現在就要解決的懸而未決事項。

- 要不要擴充到更多股票、擴充哪些股票，這裡不決定；取決於診斷結果，且明確排在「先延伸單一股票時間範圍」之後。

- 微調凍結中的視覺編碼器、或其他模型架構層級的改動是否有幫助，這一輪完全不在討論範圍內。

- 法說會逐字稿抓取流程能不能真的端到端順利執行，目前未經驗證，這一輪不處理。

- 財報內容日對日變化偏低這件事本身要不要處理（例如改變切片或沿用策略），留待之後的回合。

## Further Notes

這一輪的診斷實驗，是直接接續前一個發現而來的：把先前近乎全空的五年歷史新聞補齊之後，下游的分類準確率幾乎沒有變化（落在小測試集的雜訊範圍內），而且模型在補齊前後的每類別行為模式都一樣塌縮成只猜多數類別。這個發現，是「資料量/完整度是提升準確率的主要槓桿」這個假設從理所當然變成需要驗證的原因，也是這一輪決定先做診斷、再決定要不要繼續投資資料擴充的動機。

## 驗證結果（2026-08，診斷完成）

實作方式跟原本規劃的「備份+覆蓋+還原」略有不同、但更好：改成在融合訓練程式裡加一個記憶體內的開關（讀進新聞表徵後直接歸零，不寫回磁碟），完全不用實際備份或還原任何向量檔案，也因此拿掉了原本規劃裡「還原是否正確」的風險。四種組合（新聞有無 × 加權有無）都跑完了，並用「不開任何開關重跑一次」當回歸測試，確認結果跟改動前的基準逐位數字一致。

結果摘要：

- **不加權時，有無新聞完全沒有可量測的差異**（分類報告逐位數字相同）。代表在原本的訓練方式下，模型實質上沒有學到怎麼利用新聞這個輸入。
- **加權後，模型不再塌縮成只猜 NEUTRAL**：BEARISH f1 從 0 提升到 0.196，macro f1 從 0.247 提升到 0.303；整體 accuracy 反而從 0.46 降到 0.31 左右，這是預期中的正常現象（不加權時的高 accuracy 是靠猜多數類別灌水），不是退步。
- **加權狀態下，「有新聞」在 accuracy 與三個類別的 f1 上全面優於「沒新聞」**。這代表新聞資料確實有真實貢獻，先前只是被類別不平衡完全遮蔽，兩者存在交互作用，不是可以分開處理的獨立問題。

**結論與下一步**：類別加權（`fusion/train.py`、`classifier.py` 新增的 `--weighted` 選項，預設關閉）採納為之後訓練的預設做法。新聞資料證實有貢獻，下一步依原訂優先順序，先延伸 AAPL 時間範圍到 2026-08（對齊新聞歷史涵蓋範圍），再考慮更多股票或法說會逐字稿。誠實記錄：即使加權+有新聞，macro f1 也僅 0.303、BEARISH precision 僅 0.159，離堪用還有明顯差距，這一輪只是修掉一個方法論問題，不代表準確率已經達標，訓練細節（epoch 數、learning rate 等，屬使用者這輪明確排除的「模型」範疇）之後大機率仍需要投入。決策記錄見 `docs/decisions.md` #28。
