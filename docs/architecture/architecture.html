02 · 三個 Loss

比什麼、在哪裡算、更新誰

公式全部照計畫書 3.5 節原文，一個符號都不改；v2 只改變每個符號實際對應到什麼資料、在哪一步算。

計畫書 3.5 (4)
\[ L = \lambda_1 L_{align} + \lambda_2 L_{ground} + \lambda_3 L_{belief} \]

λ3 優先加重，λ1、λ2 作為對齊多模態與檢索訊號的結構性限制（計畫書原文）。L_align 在融合層之前、L_ground 在融合層內，都不經過 Decoder，現在沒有 GPU 也能先訓練驗證。

投影層共用（11/03 決定）：ViT、FinBERT 本體凍結，真正會被訓練的是投影 P_v、P_t、P_r。L_align、L_ground 跟融合層用同一組投影，這兩個 Loss 才會改變融合層拿到的輸入，進而影響 Z_fused、Decoder 和 RL；如果各用一組，訓練完只會改到旁邊那組，Z_fused 完全不受影響。

L_align：K 線圖 vs. K 線文字敘述

未開始
計畫書 3.5 (1)（原式）
\[ L_{align} = -\log \frac{\exp\left(\langle H_v H_t \rangle / \tau\right)}{\sum_{t'} \exp\left(\langle H_v H_{t'} \rangle / \tau\right)} \]
  • H_v：當天 K 線圖經 ViT（凍結）與共用投影 P_v 的視覺編碼，直接從 ViT 接過來，不經過融合層。
  • H_t：同一天 K 線文字敘述（Claude Haiku 讀圖寫的）經 FinBERT 與共用投影 P_t 的文字編碼。（現行程式的 H_t 仍是新聞，要改成 K 線敘述。）
  • H_{t′}：其他天的 K 線敘述；τ 是溫度參數。
  • 同型態的不同天（11/04 決定）：組 batch 時同一批不放同型態的日子（可以同時看 K 線型態和成交量標籤），K 線敘述也寫進量能、位置等細節，讓不同天的敘述不會一模一樣。公式不動。
  • 讓視覺端學會「這張圖是頭肩底」，也是 ViT domain gap 的對策之一。

L_belief：Decoder 文字 vs. LLM 產的文字

計算不變
計畫書 3.5 (3)（原式）· decoder/model.py ZFusedDecoder.forward
\[ L_{belief} = -\sum_{t=1}^{T_y} \log p_\theta\left(y_{belief,t} \mid y_{belief<t}, Z_{fused}\right) \]
  • y_belief：<TREND> [..] <RISK_LEVEL> [..] 敘述，DeepSeek 產生，格式不動；T_y 是它的長度。
  • Z_fused 以 4 個 prefix 進 Decoder。v2 的 context 依序是 [ 4 個 prefix ; RAG-2 候選短版文字 ; y_belief ]。
  • 只有 y_belief 的 token 計分；prefix 與候選文字的 label 都設成 −100。
  • y_belief 本來就是 LLM 讀當天新聞／財報／法說會寫的，context 加了候選文字後 loss 會明顯下降，這是預期內的。

L_ground：K 線敘述的文字編碼 vs. RAG-1 型態定義

α̂、α* 已選定，先試
計畫書 3.5 (2)（原式）· α̂ 取自融合層 · 現有 grounding/alpha.py 的 KL 可沿用
\[ L_{ground} = \sum_{i=1}^{K} \alpha_i^* \log \frac{\alpha_i^*}{\hat{\alpha}_i} \]
KRAG-1 檢索到的 K 段型態定義（H_r），例如「頭肩底」「W 底」「持續下跌」。
α̂（模型的注意力權重）取融合層裡 H_t token 對 H_r token 的注意力（11/04 決定）。把 H_t token 對每段定義的注意力加總，再在 K 段之間正規化。
α*（oracle 相關性分數）相似度換算，先試（11/04 決定）。H_t 跟每段 H_r 的 cosine 相似度，經 softmax 換成 K 段之間的分布。要用投影前的凍結向量還是投影後的向量，見 Q13。

意思是：K 線敘述說今天是「頭肩底」，文字端就應該把注意力放在「頭肩底」那段定義上。L_ground 只看 H_t 和 H_r 這兩組 token 之間的注意力，不經過 Decoder，現在沒有 GPU 也能算。

α* 的三個候選做法

(a) 型態類別直接對應K 線敘述的型態類別跟定義相同，就算相關。不用另外打分，但只有「對／不對」兩種。
(b) 相似度換算・採用用 H_t 跟每段 H_r 的相似度當 α*。α̂ 改取融合層的注意力後，兩邊不再是同一個式子；但 α* 若用會被訓練的投影後向量，答案卷會跟著訓練變動（Q13）。
(c) Haiku 打 0–3 分（原案，備用）流程可沿用現有的 generate_alpha_star.py，改 prompt 即可；(b) 效果不好時改用。

FinBERT 凍結、RAG-1 的檢索結果固定；α̂ 取自融合層，所以 L_ground 會直接訓練融合層本身，也透過共用投影 P_t、P_r 影響輸入。RAG-1 的 query 用 K 線圖的池化向量，不用 K 線敘述，避免跟 α* 循環。

一個例子（數字是示意）：今天的 K 線敘述是「頭肩底成形」，RAG-1 取回 3 段定義。

定義 1：頭肩底定義 2：W 底定義 3：持續下跌
H_t 與 H_r 的 cosine0.820.620.52

03 · 兩個 RAG

RAG-1 進融合層、RAG-2 進 Decoder

兩個 RAG 的語料、篩選方式、輸出位置都不同，不要混在同一個向量庫。

RAG-1：K 線型態知識

新元件・必做
L_ground 依賴它，所以一定要做 · 定義從教科書／技術分析資料庫整理
語料9 類型態各一段定義，例如「頭肩底：左肩、頭、右肩，頸線突破後偏多」。以英文撰寫（FinBERT 是英文模型），每段分「型態」「成交量」「量價判讀」三部分，對應 K 線敘述的三段。引用教科書或網路上的技術分析資料庫；找不到再用 LLM 產生＋人工校對。備用來源：StockCharts ChartSchool 型態文章（內容詳細、有各階段量能，無授權聲明，只參考改寫並註明出處）、Hugging Face propfirmkey/trading-finance-glossary-nlp（CC BY 4.0，標註出處可直接用，但每條只有一句）。
query當天 K 線圖的池化向量（ViT H_v 池化）。推論時不必等 Haiku，也不會跟 α* 循環。
輸出K 段定義編碼成 H_r，進融合層，跟 H_t、H_v 一起做 self-attention。
\[ H_r = \big[\mathrm{FinBERT}(k_{j_1});\dots;\mathrm{FinBERT}(k_{j_K})\big],\quad \{k_{j}\} = \operatorname{top-}K_{k\in\mathcal{KB}}\ \cos(q, e_k) \]
  • L_ground 比較融合層裡 H_t 對這 K 段定義的注意力 α̂，與相似度換算的 α*。
  • 同一組 H_r 也進融合層，跟 H_t、H_v 一起做 self-attention。

只生成一次：Decoder 看 Z_fused 的同時就看候選

已選定，有兩個風險要盯

context 裡同時有 Z_fused 的 prefix 和 RAG-2 的候選文字，Decoder 生成時的注意力自然會參考 Z_fused 來決定看哪幾段，等於「看 Z_fused 的時候同時查」。不需要另外學 query（W_q），也不用跑兩次。

可解釋性從哪來：候選的短版原文就在 context 裡，敘述可以直接引用；Decoder 對各段候選的注意力可以畫出來，標出每句話主要參考哪幾段（只用來展示，不算 Loss）。

風險 ① 只抄文件、不看圖候選文字一開始就在 context，Decoder 很可能完全忽略 Z_fused。評估以「型態一致率」為主：Decoder 敘述的型態跟 Haiku 敘述一不一致。型態一致率分不出 Decoder 是看圖還是從文件抄，所以再補「打亂 Z_fused」當輔助檢查：換成別天的 Z_fused，敘述裡的型態應該要跟著變。
風險 ② context 變長現行 Decoder 用 max_length 512。加上 15–20 段短版文字（約 600–800 token）後，序列大約 1,100–1,300 token，這是主線，等有 GPU 再跑。不加 RAG-2 的 512 版本是選配，可以先在 Mac 跑。
04 · 分階段計畫

先做什麼、後做什麼

沿用「沒有運算資源前先用第一階段方法驗證」的原則。L_align 與 L_ground 都在 Decoder 之前，現在就能訓練。

現在可做
  1. 寫 Haiku 讀圖 prompt（9 類型態），三檔股票產生 K 線文字敘述並存檔（只需 API）。
    先抽幾十天人工看過，確認型態判斷合理。
  2. 整理 RAG-1 型態定義知識庫：從教科書或技術分析資料庫整理 9 段英文定義（備用來源：ChartSchool、HF trading-finance-glossary-nlp），找不到的用 LLM 產生＋人工校對；建索引。
  3. 算 α* 答案卷：H_t 與各段 H_r 的相似度換算（用哪份向量見 Q13）。
  4. 融合層輸入改成 H_t（K 線敘述）＋H_v＋RAG-1 的 H_r，輸入投影改成共用的 P_v、P_t、P_r，拿掉新聞與舊 H_r。
  5. 訓練 L_align＋L_ground（batch 避開同型態；α̂ 取融合層注意力），用第一階段方法驗證：分類器、型態類別的線性 probe、α̂ 跟 α* 的一致率、遮掉 H_t 的消融。
  6. 建 RAG-2 候選篩選：日期過濾、固定章節（MD&A、風險因素開頭）、短版文字；人工抽查幾天的候選。
  7. Decoder 端程式：候選放進 context、複合 Loss；小模型 smoke test。
  8. （選配）Mac 上跑不加 RAG-2 的 512 版本：先看新的 Z_fused（K 線敘述＋RAG-1）對 Decoder 有沒有幫助。
需要運算資源
  1. Decoder 聯合訓練（主線）：加 RAG-2 候選，context 約 1,100–1,300 token。
  2. 評估：TREND／RISK 準確率、LLM-judge、型態一致率（主）、打亂 Z_fused（輔助）。
  3. 解讀 L_belief：測試完看結果再決定怎麼解讀。
  4. 消融：只用 L_belief／＋L_align／＋L_ground／三個一起；有無 RAG-2 候選；遮掉 H_t。

Q13 · L_ground

α* 用哪一份向量算相似度？

  • B · 用共用投影後的向量，但 α* 不回傳梯度
    答案卷會隨投影慢慢變，但不會被直接拉向 α̂
